# ТАБЛО — результаты и расписание

Сайт на одном файле: футбол (6 турниров), UFC и Формула-1. Без сборки, без npm, без бэкенда.

---

## Стадии турниров

Раньше сайт врал: в Лиге чемпионов появлялись «400-й тур» и подобное. Причина — у TheSportsDB поле `intRound` содержит не только номер тура, но и **коды стадий**:

| Код | Стадия |
|---|---|
| 125 | Четвертьфинал |
| 150 | Полуфинал |
| 160 | Раунд плей-офф |
| 170 | Полуфинал плей-офф |
| 180 | Финал плей-офф |
| 200 | Финал |
| 400 | Квалификация |
| 500 | Предсезонный матч |

Теперь эти коды разбираются в функции `stageFromTSDB`, а Лига чемпионов дополнительно помечается как «Общий этап» — в формате с 2024/25 туры 1–8 идут именно там, а не в группах.

Важное правило: **если код незнакомый, метка не выводится вообще**. Лучше пустой рельс, чем выдуманный номер тура. Список кодов не полный — например, для 1/8 финала своего кода в документации нет.

Если нужна стопроцентная точность стадий, переключайся на API-Football: он отдаёт стадию строкой («Round of 16», «League Stage - 3», «Knockout Round Play-offs»), и функция `stageFromAF` переводит её напрямую. Ничего угадывать не приходится.

## Турнирная таблица

Полная таблица со всеми командами: игры, победы, ничьи, поражения, мячи, разница, очки, плюс **форма — пять последних матчей** значками В / Н / П.

Форма приходит от API готовой: TheSportsDB отдаёт её в поле `strForm` строкой вида `WLWLW`, API-Football — в поле `form`. Считать самому ничего не нужно.

Зоны турнира тоже берутся из API — поле `strDescription` (`description` у API-Football) содержит текст вроде `Promotion - Champions League (Group Stage)` или `Relegation - Championship`. Функция `zoneOf` разбирает его в четыре зоны, каждая получает свою полосу слева и попадает в легенду под таблицей:

| Полоса | Зона |
|---|---|
| Золотая | Лига чемпионов |
| Синяя | Лига Европы |
| Зелёная | Лига конференций |
| Красная | Вылет |

Порядок проверок в `zoneOf` важен: «вылет» ищется первым, иначе `Relegation - Championship` зацепится не за то правило.

### Как получить таблицу целиком

Бесплатный ключ TheSportsDB возвращает **только 5 строк** вместо 20 — проверено на живом запросе, обойти это никак нельзя. Поэтому таблица берётся из лучшего доступного источника, по порядку:

| Приоритет | Источник | Что даёт | Нужен ключ |
|---|---|---|---|
| 1 | **football-data.org** | вся таблица + форма, 6 турниров | да, бесплатный навсегда |
| 2 | API-Football | вся таблица + форма | да, сезоны ограничены |
| 3 | **OpenLigaDB** | вся таблица, только Бундеслига | **нет** |
| 4 | TheSportsDB | 5 строк | запасной вариант |

**OpenLigaDB работает сразу, без всякой настройки** — это открытый немецкий проект, ключа он не требует вообще. Поэтому таблица Бундеслиги показывается полностью прямо из коробки. Минусы: покрывает только немецкие лиги и не отдаёт форму последних матчей, а поскольку это community-проект, иногда отвечает ошибкой — тогда включается запасной источник.

Под таблицей всегда написано, откуда она пришла и сколько в ней строк, — гадать не нужно.

**Включить полную таблицу.** Возьми бесплатный ключ на `football-data.org/client/register` и впиши одну строку:

```js
const CONFIG = {
  fdKey: "твой-ключ",
  ...
};
```

Больше ничего менять не надо: коды турниров (`PL`, `PD`, `SA`, `BL1`, `FL1`, `CL`) уже проставлены в `SPORTS` полем `fdCode`. Матчи, туры и календарь при этом продолжат работать через свой источник — переключается только таблица.

### Названия немецких клубов

OpenLigaDB отдаёт названия в официальном виде: `Bayer 04 Leverkusen`, `1. FSV Mainz 05`, `1. FC Heidenheim 1846`. Функция `clubKey` вычищает цифры и клубные приставки (`FC`, `VfB`, `TSG`, `FSV`, `SV`, `VfL`), чтобы русский словарь срабатывал и на них.

### Про зоны еврокубков

TheSportsDB и API-Football присылают зону текстом (`Promotion - Champions League`), и он используется как есть. **football-data.org такого поля не отдаёт**, поэтому для него зона считается по месту в таблице — правила лежат в объекте `ZONES`.

Это приближение: реальное число мест в Лигу чемпионов зависит от коэффициента страны и итогов кубков и может отличаться на одну позицию. Если для твоей лиги важна точность, поправь числа в `ZONES` вручную.

### Названия клубов из разных API

Один клуб приходит по-разному: `FC Barcelona`, `Barcelona`, `Real Madrid CF`, `FC Bayern München`. Функция `clubKey` снимает диакритику и типовые приставки с окончаниями, чтобы словарь `CLUBS_RU` срабатывал независимо от источника.

## Бомбардиры и ассистенты

### Ограничение по сезонам

API-Football пишет, что все тарифы включают все турниры и эндпоинты, но **бесплатный тариф ограничен по доступным сезонам** — текущий он обычно не отдаёт. Из-за этого статистика игроков выглядела прошлогодней без всякого предупреждения.

Теперь функция `afResolveSeason` шагает от свежего сезона к старому, пока не придут данные, и запоминает найденный год, чтобы не тратить запросы повторно. Если год оказался не текущим, под таблицей появляется строка «Показаны данные за сезон 2023/2024» — цифры больше не выдают себя за свежие.

Вкладка «Игроки» с переключателем между голами и голевыми передачами. Колонки: место, игрок, клуб, матчи, голы, пас, пенальти. Активная метрика подсвечена золотым.

Источник — только API-Football:

```
/players/topscorers?league=39&season=2026
/players/topassists?league=39&season=2026
```

Оба возвращают 20 игроков с полным профилем статистики, так что голы и передачи приходят в одном ответе. **У TheSportsDB такого метода нет вообще** — на нём вкладка покажет демо-заглушку и строку с объяснением. Это не баг, а ограничение источника.

### Про демо-данные игроков

Имена в `DEMO_PLAYERS` — заглушка для вёрстки, а не настоящая статистика. Числа сгенерированы, составы могут быть неактуальны. Как только подключишь API-Football, всё заменится реальными данными.

## Тур и календарь

Две вкладки, которые появляются только у футбола.

**Тур** — все матчи одного тура на одном экране, со стрелками переключения. Номер тура при открытии выбирается сам: берётся тур того матча, который ближе всего к сегодняшнему дню. Данные идут через `eventsround.php?id=<лига>&r=<тур>&s=<сезон>`.

**Календарь** — сетка месяца. Числа с золотой точкой означают, что в этот день есть матчи; клик по числу выводит список игр под календарём. За день отвечает `eventsday.php?d=ГГГГ-ММ-ДД&l=<лига>`.

Точки на числах строятся из уже загруженных результатов и расписания — то есть покрывают примерно месяц вокруг сегодня. Клик работает по любому числу, даже без точки: запрос за этот день уйдёт в любом случае.

### Ограничение бесплатного ключа

`eventsseason.php` (весь сезон одним запросом) на бесплатном ключе возвращает ровно **15 матчей**, а не сезон целиком — я это проверил. Поэтому календарь и тур ходят за данными точечно, по одному туру и по одному дню, а не грузят сезон и работают локально. С премиум-ключом или на API-Football можно переписать на один запрос за сезон и убрать все остальные — логика уже разделена, менять придётся только блок 6.

## Языки

Кнопка RU / UZ в шапке. При первом заходе язык берётся из настроек браузера: если он узбекский — включается UZ, иначе RU.

Все тексты собраны в объекте `I18N`. Чтобы добавить третий язык, скопируй блок `uz` и переведи.

Две вещи, о которых стоит знать:

1. **Узбекские даты форматируются вручную.** У браузеров нет узбекских названий месяцев — `Intl` возвращает «M08 25, Tue» вместо «Sesh, 25-avgust». Поэтому для UZ используются массивы `UZ_MONTHS` и `UZ_DOW`.
2. **Названия клубов приходят из API на английском.** Для русского есть словарь `CLUBS_RU` (Bayern Munich → Бавария). Он неполный — дополняй по мере надобности, незнакомые названия просто остаются в оригинале. Для узбекского словаря нет: в узбекской спортивной прессе принято оставлять оригинальное написание.

## Оформление

Тема золотисто-белая. Все цвета — переменные в начале блока `<style>`, менять только там:

```css
--gold:      #F2B417;   /* заливки, активные состояния */
--gold-deep: #9A6B04;   /* золото для текста по белому  */
--sand:      #FAF6EC;   /* фон страницы                 */
--paper:     #FFFFFF;   /* карточки                     */
```

Счёт сыгранного матча выводится золотой пластиной, ещё не сыгранный — только контуром со временем начала, идущий прямо сейчас — красным. Это не украшение: по одному взгляду на пластину видно статус матча, не читая подписи.

Под пластиной стоит дата в формате «пт, 28.08». Она нужна прежде всего во вкладке «Тур» и в календаре, где матчи идут подряд за разные дни и заголовка дня над ними нет. В «Результатах» и «Расписании» она дублирует заголовок дня — это сделано намеренно, чтобы карточка матча читалась сама по себе, если на неё смотрят вне списка. Если дубль не нужен, достаточно передать `flat` в `renderList` и убрать вызов `scoreDateHTML` для сгруппированных списков.

## Запуск

Просто открой `index.html` двойным кликом. Сайт заработает сразу, но покажет **демо-данные** — об этом честно скажет оранжевая плашка сверху. Так и должно быть, ниже объясню почему.

Чтобы пошли настоящие данные, запусти локальный сервер:

```bash
# в папке с index.html
python3 -m http.server 8080
# затем открой http://localhost:8080
```

## Откуда берутся данные

### Почему не Flashscore

У Flashscore нет публичного API — официального канала доступа к данным для сторонних разработчиков они не открывают. Всё, что находится в поиске под названием «Flashscore API», — это чужие скраперы, которые парсят сайт в обход правил. Использовать их нельзя по трём причинам:

1. Это нарушает условия использования Flashscore.
2. Сами результаты Flashscore лицензирует у поставщиков спортивных данных — то есть перепубликация чужой лицензии.
3. Из статичного сайта в браузере это технически не работает: CORS, защита от ботов, страницы собираются скриптами.

Если данные Flashscore нужны именно как продукт — их владелец, компания Livesport, продаёт официальные data feeds по договору. Это B2B и платно.

### Что используется вместо

**TheSportsDB** — включён по умолчанию, работает сразу. Один API покрывает все три вида спорта.

**API-Football** — по покрытию и скорости обновления ближе всего к Flashscore: живые счета, все крупные лиги, таблицы, статистика. Нужен свой ключ, бесплатный тариф — 100 запросов в сутки. Адаптер уже написан, включается одной строкой:

```js
const CONFIG = {
  provider: "apifootball",   // ← было "thesportsdb"
  afKey: "твой-ключ-отсюда: dashboard.api-football.com",
  ...
};
```

Работает для футбола. UFC и Формула-1 остаются на TheSportsDB — у API-Football это отдельные продукты с отдельными ключами.

ID лиг для API-Football уже проставлены в `SPORTS` полем `afId` (АПЛ — 39, Ла Лига — 140, Серия А — 135, Бундеслига — 78, Лига 1 — 61, ЛЧ — 2). Если какая-то лига отдаёт пусто — сверь ID в личном кабинете, они иногда меняются.

В файле сейчас стоит бесплатный тестовый ключ `123`. Он общий на всех, часть методов урезана, для настоящего сайта заведи свой аккаунт и подставь ключ здесь:

```js
const CONFIG = {
  apiKey: "123",   // ← сюда свой ключ
  ...
};
```

### Лимиты бесплатного ключа — главная засада

Строка «Free Limit» в документации TheSportsDB означает **количество событий в ответе**, а не число запросов. Я замерил на живых запросах:

| Запрос | Бесплатный ключ | Премиум |
|---|---|---|
| `eventspastleague` | **1 матч** | 20 |
| `eventsnextleague` | **1 матч** | 20 |
| `eventsround` | 5 матчей | — |
| `eventsseason` | 15 матчей | 3000 |
| `eventsday` | 3 матча | 1500 |
| `lookuptable` | 5 строк | 100 |

Первая версия сайта грузила результаты и расписание через `eventspastleague` / `eventsnextleague` — то есть показывала **по одному матчу**, даже когда сеть работала исправно. Это выглядело как поломка, но было ограничением источника.

Сейчас логика другая:

1. Один дешёвый запрос `eventspastleague` определяет текущий тур и сезон — из единственного матча берутся поля `intRound` и `strSeason`.
2. Матчи забираются через `eventsround` за три тура вокруг текущего.

Четыре запроса вместо одного, зато **15 матчей вместо одного**. Для UFC и Формулы-1 туров нет, поэтому там используется `eventsseason` — тоже 15 событий вместо одного.

При 30 запросах в минуту на бесплатном ключе этого хватает с запасом, тем более что ответы кэшируются на 60 секунд.

---

### Важно: CORS

Браузер запрещает запросы к чужому домену, если сервер не разрешил их явно. Теперь сайт **сам объясняет причину** в оранжевой плашке — гадать не нужно. Возможные сообщения:

| Что показано | Что делать |
|---|---|
| Страница открыта с диска (file://) | Запустить локальный сервер |
| Браузер заблокировал запрос (CORS) | Поставить прокси |
| Слишком много запросов | Подождать минуту, лимит 30/мин |
| API ответил ошибкой 401 / 403 | Проверить ключ в `CONFIG` |
| API не ответил вовремя | Проверить интернет |
| API ответил, но матчей не вернул | Межсезонье или пауза в турнире |

Если нужен прокси-посредник: Он же решает вторую проблему: **ключ API не будет виден в исходниках страницы**.

Самый простой бесплатный вариант — Cloudflare Worker:

```js
export default {
  async fetch(request) {
    const { pathname, search } = new URL(request.url);
    const target = `https://www.thesportsdb.com/api/v1/json/ТВОЙ_КЛЮЧ${pathname}${search}`;
    const res = await fetch(target);
    return new Response(res.body, {
      status: res.status,
      headers: {
        "Content-Type": "application/json",
        "Access-Control-Allow-Origin": "*",
        "Cache-Control": "public, max-age=60"
      }
    });
  }
};
```

Задеплой его на `workers.dev` и поменяй в `index.html`:

```js
const CONFIG = {
  apiKey: "",                                  // ключ теперь на сервере
  base: "https://твой-worker.workers.dev",     // без ключа в пути
  ...
};
```

Плюс убери `${CONFIG.apiKey}/` из функции `getJSON`.

## Как менять турниры

Всё в объекте `SPORTS` в начале скрипта. Добавить лигу — одна строчка:

```js
{ id: "4344", label: "РПЛ", season: footballSeason() }
```

ID лиги можно подсмотреть в адресе страницы на сайте TheSportsDB: `thesportsdb.com/league/4328-...` → `4328`.

Уже подключено:

| Турнир | ID |
|---|---|
| Лига чемпионов | 4480 |
| АПЛ | 4328 |
| Ла Лига | 4335 |
| Серия А | 4332 |
| Бундеслига | 4331 |
| Лига 1 | 4334 |
| UFC | 4443 |
| Формула-1 | 4370 |

Сезон для футбола считается сам: с июля начинается новый (`2026-2027`). Для UFC и Ф-1 — просто текущий год.

## Что уже есть

- Два языка: русский и узбекский, переключение без перезагрузки
- Вкладка «Тур»: все матчи одного тура сразу, со стрелками переключения
- Календарь месяца: клик по числу показывает матчи этого дня
- Правильные названия стадий вместо номеров туров в кубковых турнирах
- Полная турнирная таблица с формой последних 5 матчей и зонами еврокубков
- Бомбардиры и ассистенты с переключателем
- Три раздела с отдельной навигацией внутри каждого
- Результаты и расписание для всех видов спорта, плюс турнирная таблица для футбола
- Группировка матчей по игровым дням
- Время пересчитывается в часовой пояс посетителя
- Поиск по команде
- Автообновление раз в 2 минуты и кнопка обновления
- Индикатор идущего матча (зелёная пульсирующая точка)
- Скелетоны при загрузке, честные состояния при ошибке и пустом ответе
- Кэш ответов на 60 секунд, чтобы не долбить API
- Адаптив до 360px, видимый фокус с клавиатуры, `prefers-reduced-motion`

## Чего нет

- Составов, статистики матча, трансляций

- Полного карда UFC по боям — в бесплатном тарифе отдаются только сами турниры

В папке лежат два скрипта на Playwright:

- `mock.py` — поддельный TheSportsDB с теми же лимитами, что у бесплатного ключа (1 матч из `eventspastleague`, 5 из `eventsround`, 5 строк таблицы).
- `regress.py` — прокликивает все вкладки всех трёх разделов на обоих языках, затем проверяет интерактив: стрелки туров, листание месяца, клик по числу, переключение бомбардиров и ассистентов. Ловит любые ошибки JS.

```bash
pip install playwright && python3 -m playwright install chromium
python3 regress.py
```

Этот тест появился не просто так. Функции `roundNavHTML` и `calendarHTML` однажды были случайно стёрты при правке соседнего блока кода — вкладки «Тур» и «Календарь» падали с `ReferenceError`. Проверка синтаксиса такое не ловит, потому что ошибка возникает только во время выполнения. Прогоняй `regress.py` после любой правки скрипта.

## Структура кода

Скрипт разбит на 7 пронумерованных блоков, искать по комментариям:

1. Конфигурация — ключи, лиги, сезоны
2. Языки — все тексты интерфейса
3. Состояние
4. Утилиты — экранирование, форматы дат
5. Стадии турниров — разбор кодов и строк
6. Слой данных — **все запросы к API только здесь**
7. Демо-данные
8. Отрисовка
9. Контроллер и обработчики

Блок 5 (стадии турниров) и блок 6 (слой данных) — те места, где живёт вся работа с внешними API.

Если будешь менять источник данных — трогать нужно только блок 4 и функцию `normalizeEvent`. Вся отрисовка работает с единым форматом объекта и об API ничего не знает.
